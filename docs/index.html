Which pages should an editor review first? Ranking content-refresh candidates on held-out clients

Rajkumar · FlyRank ML Internship capstone (Lane 2: refresh / content opportunity scoring) · code & notebooks

Abstract

Question: which existing pages should an editor review first because their search traffic is declining? Data: the FlyRank ML Internship starter dataset of 30,000 anonymized pages from 32 clients, labelled by trend_direction == "down". Method: a hand-written baseline rule versus logistic regression, random forest and HistGBM, all evaluated on the same split with 7 clients fully held out (6,163 test pages, base rate 0.511), after a leakage check. Result: the hand rule ranked worse than random (AUC 0.463, Precision@50 0.36), while logistic regression reached AUC 0.631 and Precision@50 0.82. Use: decision-support for ordering editorial reviews, not a forecast or causal claim.

1. Problem

An editor cannot review every page each month. The decision this supports is the order of the review queue: put pages most likely to be declining at the top. The metric is Precision@50 on held-out clients, always shown next to the base rate, with ROC AUC alongside.

2. Data

  • 30,000 pages, 32 clients, one row per page (grain verified). Rows per client range from 3 to 7,008 (median 567).
  • Label base rate: 0.542 overall, 0.594 among pages with at least 1k impressions in 90 days.
  • word_count is missing on 7,699 rows (25.7%).
  • Only the bundled starter CSV was used, not the gated full warehouse. No client names appear here.

3. Methodology

Split: 25 train clients, 7 test clients, no overlap; seed 42. Leakage check: with the same random forest and split, safe features gave AUC 0.626; adding trend_pct gave AUC 1.000 and adding the 30-day windows gave 0.895. Both leak the label and were excluded. Baseline: a hand rule weighting age, staleness, visibility and a position 4–20 bonus.

Signal audit: decline rate is 0.60–0.64 for pages up to 236 days old but 0.42 for pages older than 333 days, the opposite of the "old pages decay" intuition. Competition level does not separate classes (0.556 / 0.563 / 0.567).

Top-50 precision went from 0.36 (hand rule) to 0.82 (logistic regression) against a base rate of 0.511. Top random-forest permutation importances: days_with_impressions, avg_position, content_age_days. The model ranks worse on high-visibility pages (AUC 0.581) than low-visibility ones (AUC 0.651).

5. Limitations & honest framing

  • A random row split overstates performance: the same random forest scores AUC 0.769 / P@50 0.94 on a row split versus 0.626 / 0.74 on the client holdout.
  • The 90-day features overlap the label window; this is a known limit.
  • AUC around 0.63 is modest discrimination. Results come from the starter sample only.
  • Paper Finding #1 ("growing content is longer") was not reproduced in this sample: median word count 2,848 growing vs 2,909 declining; growing pages longer in only 18 of 30 clients.
  • Claims are observed and measured, predictive not causal.

6. Ranked recommendations

  1. Order reviews by model score, not by page age: the age rule is backwards in this data.
  2. Exclude pages under 100 impressions (7,994 pages) from action.
  3. Queue from this run: refresh 2,951 · refresh_and_review_ctr 4,872 · review 10,509 · monitor 11,668. A human reviews before any change.
  4. Next step: replace baseline-derived reason codes with model-based ones.
